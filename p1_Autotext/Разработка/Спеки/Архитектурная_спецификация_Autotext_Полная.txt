# Архитектурная спецификация: Autotext (вариант «Полная»)

**Проект:** нейросеть для автодополнения текстов (предсказание следующего слова)  
**Версия:** 1.0  
**Статус:** Утверждена как целевой профиль по параметрам ТЗ  
**Синхронизация:** `ТЗ_Autotext.txt`, `План_реализации_Autotext.txt`  
**Цель профиля:** обучение на полном (или почти полном) WikiText-2 с гиперпараметрами старта из ТЗ; предпочтительно GPU / учебная ВМ

---

## 1. Назначение варианта

Полный учебный профиль. Соответствует стартовым параметрам из ТЗ и даёт более представительные абсолютные значения perplexity для сравнения LSTM и GRU.

Использовать, когда есть GPU (локально или учебная ВМ на 3–5 часов работы; лимит жизни ВМ в ТЗ — 7 часов).

В ячейке констант указать: `CONFIG = "full"`.

---

## 2. Согласованные решения

| Пункт ТЗ | Реализация в профиле «Полная» | Обоснование |
|----------|-------------------------------|-------------|
| WikiText-2 | Полные split train/validation/test | Стандартный бенчмарк |
| Пословный словарь | Порог частоты умеренный (например 2–3) | Баланс покрытия и размера vocab |
| LSTM | Embedding + LSTM + Linear, 2 слоя | Стартовая архитектура из ТЗ |
| GRU | Та же ширина/глубина, замена ячейки | Честный эксперимент |
| Hyperparams | Как в ТЗ: 128 / 256 / 2 / 32 / 64 / 0.001 | Базовая точка сравнения |
| Gradient clipping | Обязателен | Стабилизация обучения |
| distilgpt2 | Без дообучения; perplexity на полном test (или большой доле) | Представительная оценка |
| Сравнение | Таблица + 5–10 общих контекстов + рекомендация | Чек-лист этапа 5 |
| Формат сдачи | Один Jupyter-ноутбук | Стиль Карпати: линейный рассказ |

Отклонений от формальной задачи ТЗ нет. От профиля «Ноутбук» отличается только объёмом данных и размером сети.

## 3. Общая архитектура пайплайна

```text
WikiText-2 (datasets) — полные split'ы
        │
        ▼
  Фильтр пустых строк + EDA (+ визуализации)
        │
        ▼
  Пословный словарь (только train, min_freq)
        │
        ▼
  Окна seq_len=32 → Dataset / DataLoader
        │
        ├────────────────┬────────────────────┐
        ▼                ▼                    ▼
   LSTM (full train) GRU (full train)  distilgpt2 (eval)
        │                │                    │
        └────────────────┴────────────────────┘
                         │
                         ▼
           Сводная таблица + примеры + рекомендация PM
```

Стиль кода тот же, что в профиле «Ноутбук»: один ноутбук, один класс модели, переключатель `CONFIG`.  
Разница — значения констант и доля данных, не структура классов.

## 4. Контракты компонентов

### 4.1. Данные → словарь

```python
interface Vocab:
    word2idx: dict[str, int]
    idx2word: list[str]
    unk_token: "<unk>"
    # строится только по train
    # слова с count < MIN_FREQ → <unk>
```

Правила:
- валидация и тест не расширяют словарь;
- lower + split по пробелам;
- спецтокены минимум: `<unk>` (при необходимости `<pad>` не обязателен, если хвосты отбрасываются).

### 4.2. Словарь → окна

```python
interface WindowBatch:
    X: LongTensor[B, seq_len - 1]
    Y: LongTensor[B, seq_len - 1]
```

Сдвиг на 1 токен обязателен (формальная постановка ТЗ).  
Окна неперекрывающиеся или со сдвигом `seq_len` — зафиксировать в ноутбуке один способ и не менять между LSTM и GRU.

### 4.3. Модель

```python
interface LanguageModel(nn.Module):
    emb: Embedding(vocab_size, emb_dim=128)
    rnn: LSTM | GRU (
           input_size=128,
           hidden_size=256,
           num_layers=2,
           batch_first=True
         )
    fc:  Linear(256 → vocab_size)
    forward(x) -> logits[B, T, vocab_size]
```

Скрытое состояние: обнулять на каждом батче/окне (простая LM без BPTT через документы) — явно описать в ячейке.

### 4.4. Обучение

```python
interface TrainStep:
    loss = CrossEntropyLoss(logits.view(-1, V), Y.view(-1))
    loss.backward()
    clip_grad_norm_(model.parameters(), CLIP_NORM)
    optimizer.step()
```

На эпоху: train loss; на val: loss и perplexity = exp(val_loss).

### 4.5. distilgpt2

```python
tokenizer = GPT2TokenizerFast.from_pretrained("distilgpt2")
model = GPT2LMHeadModel.from_pretrained("distilgpt2")
# eval only, no fine-tuning
```

Perplexity на test по BPE. В отчёте: «шкала не сопоставима напрямую с LSTM/GRU».

## 5. Гиперпараметры профиля «Полная»

| Параметр | Значение | Источник |
|----------|----------|----------|
| `CONFIG` | `"full"` | Этот документ |
| `seed` | `42` | Чек-лист ТЗ |
| `device` | `cuda` при наличии, иначе `cpu` | Практика |
| `SEQ_LEN` | `32` | ТЗ |
| `EMB_DIM` | `128` | ТЗ |
| `HIDDEN_DIM` | `256` | ТЗ |
| `NUM_LAYERS` | `2` | ТЗ |
| `BATCH_SIZE` | `64` | ТЗ |
| `LR` | `0.001` | ТЗ |
| `EPOCHS` | `5–10` (пока val ppl снижается) | Практика + чек-лист |
| `CLIP_NORM` | `1.0` | ТЗ (gradient clipping) |
| `MIN_FREQ` | `2` или `3` | Умеренный словарь |
| `TRAIN_FRACTION` | `1.0` | Полный train |
| `VAL_FRACTION` | `1.0` | Полный val |
| `TEST_FRACTION_RNN` | `1.0` | Полный test для LSTM/GRU |
| `TEST_FRACTION_GPT` | `1.0` (на CPU допустимо 0.25–0.5) | Представительность |
| `NUM_WORKERS` | `0` на Windows; `2–4` на Linux VM | Платформа |
| Оптимизатор | Adam | Стандарт |
| Loss | CrossEntropyLoss | ТЗ |

Ожидаемый порядок размера модели: миллионы параметров (зависит от vocab).  
Время: комфортно на GPU; на CPU полный профиль может выйти за разумные часы — тогда использовать профиль «Ноутбук».

## 6. Этапы реализации (ячейки ноутбука)

### Этап 0. Подготовка
- Зависимости из `requirements_sprint2_project.txt` (когда файл появится в окружении курса).
- Импорты, `seed = 42`, `CONFIG = "full"`, выбор device.

### Этап 1. Данные
- Загрузка WikiText-2 raw v1.
- Разведочный анализ с визуализациями.
- Пословная токенизация и словарь.
- Последовательности фиксированной длины, Dataset/DataLoader.
- Демонстрация сдвига X/Y.

### Этап 2. LSTM
- Класс Embedding + LSTM + Linear.
- Цикл с train/val loss и val perplexity.
- Gradient clipping.
- Обучение до снижения val perplexity.
- Графики обучения.

### Этап 3. GRU vs LSTM
- GRU с теми же гиперпараметрами.
- Сравнение: perplexity, число параметров, время на эпоху.
- Вывод по эксперименту.

### Этап 4. distilgpt2
- Загрузка модели и токенизатора.
- Perplexity на test.
- Примеры предсказаний.

### Этап 5. Сравнение и выводы
- Сводная таблица всех моделей.
- 5–10 одинаковых контекстов.
- Рекомендации продакт-менеджеру с учётом мобильных ограничений (размер, скорость) и оговоркой про несравнимость шкал perplexity.

---

## 7. Рекомендации по ВМ / GPU (из ТЗ)

1. Проект рассчитан на 3–5 часов; ВМ живёт до 7 часов — не держать машину «вхолостую».
2. Сначала прогнать этап 1 (данные) и короткий smoke-train (1 эпоха, маленький batch) — проверить, что пайплайн живой.
3. Затем полные LSTM и GRU одной сессией, потом distilgpt2 eval.
4. Сохранять графики и таблицу в ноутбуке до отключения ВМ.

---

## 8. Ограничения и честность отчётности

1. Не сравнивать числа perplexity LSTM/GRU и distilgpt2 как одну шкалу.
2. Картинка «Мой банк» — иллюстрация продукта; обучение на английском WikiText-2.
3. В рекомендациях PM: переносить размер/latency/качество подхода; не утверждать, что модель выучила банковский русский словарь.
4. При нехватке GPU переключаться на профиль «Ноутбук», не ломая структуру ноутбука — только константы и доли данных.
