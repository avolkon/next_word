# Инструкция агенту: сдача Nutrition как отдельный GitHub-репозиторий

Документ для **нового чата / агента**. Цель — воссоздать на GitHub репозиторий сдачи так, чтобы история и структура выглядели **как у человека-студента**, а не как одноразовый dump от ИИ.

## Источник правды (локально)

Черновик сдаточной структуры уже лежит здесь:

```text
next_word/p2_Nutrition/avo_Nutrition_rep/
```

Рабочая «кухня» (ТЗ, CPU-прогоны, полный zip) — рядом в `p2_Nutrition/Разработка/`. В публичный/сдаточный репозиторий **не** тащить `Разработка/`, CPU-чекпоинты C1–C7, дубли Colab-ноутбуков без нужды.

## Целевая структура репозитория (как в ТЗ)

```text
<repo-root>/
  data/                 # dish.csv, ingredients.csv, images/…  ИЛИ только csv + README «положи zip»
  scripts/
    dataset.py
    utils.py
    config_full.py      # ок оставить — используется ноутбуком
    __init__.py
  artifacts/            # .gitkeep; best.pt после обучения (часто в .gitignore)
  avo_m25_555_nutrition.ipynb
  requirements.txt
  README.md
  .gitignore
```

Имя репо на GitHub — нейтральное, студенческое, например: `nutrition-calories`, `calorie-prediction`, `avo-m25-555-nutrition`. **Не** называть `next_word`, `cursor-export`, `ai-generated`.

## Как сделать историю «как у человека»

### Принципы

1. **Несколько коммитов во времени**, не один mega-commit «init everything».
2. Сообщения — короткие, в стиле студента (RU или EN, но **один язык на весь репо**), без «Generated by Cursor» / «Agent:».
3. Порядок коммитов ≈ реальный ход проекта (сначала каркас → данные/пути → scripts → EDA → train → инференс/README).
4. Ноутбук с **сохранёнными outputs** — только в позднем коммите (после «обучения»), либо отдельным «save notebook outputs».
5. Тяжёлые бинарники (`nutrition.zip`, `images/`, `*.pt`) — либо не в git (ссылка в README), либо один поздний коммит / Git LFS. Не размазывать GB по ранним коммитам.
6. **Не** копировать служебные папки агента, `Правила/`, чужие проекты (`p1_`, `p3_`), `_tmp`, dump-скрипты.

### Рекомендуемая последовательность коммитов (шаблон)

Делать **по одному** `git add` + `git commit` на шаг. Даты можно оставить естественными (день за днём) — **не** подделывать `GIT_AUTHOR_DATE`, если пользователь явно не просил; реалистичность важнее фейковых timestamps.

| # | Что добавляем | Пример message |
|---|---------------|----------------|
| 1 | `README.md` (черновик), `requirements.txt`, `.gitignore` | `init: project stub and dependencies` |
| 2 | пустой `data/.gitkeep` или только `data/README.md` с описанием структуры | `docs: describe dataset layout` |
| 3 | `scripts/dataset.py` (+ `__init__.py`) | `feat: dataset and dataloaders` |
| 4 | `scripts/utils.py` | `feat: multimodal model and train()` |
| 5 | `scripts/config_full.py` | `feat: full-run config after cpu search` |
| 6 | ноутбук **без** тяжёлых outputs / почти пустой каркас этапов | `notebook: eda and training skeleton` |
| 7 | доработки scripts по багам (если были) | `fix: …` (только реальное) |
| 8 | финальный ноутбук с outputs + MAE в README | `results: full run metrics and error analysis` |
| 9 | (опционально) `artifacts/best.pt` через LFS или «скачать отдельно» в README | `chore: ignore checkpoints` / LFS add |

Если пользователь уже всё сделал в одном файле — **не** выдумывать фейковые промежуточные версии кода. Лучше 4–6 честных коммитов по слоям файлов (stub → scripts → notebook → results), чем поддельные diff’ы.

### Чего избегать (сразу палит «бота»)

- Один commit: `Initial commit` со всем сразу (ноутбук + scripts + 1.4GB data).
- Commit messages вроде `Update files`, `Changes`, `Fix stuff`, `WIP WIP WIP` пачкой без смысла.
- Идеально ровные 10 коммитов с шаблонными Conventional Commits на каждое чихание.
- В README: «This repository was created by an AI agent…».
- Абсолютные пути `C:\Users\...` в коде и README.
- Два одинаковых ноутбука (`*_Colab` + `avo_*`) без пояснения — оставить **один** сдаточный.

## Пошаговый протокол для агента (когда пользователь дал пустой GitHub repo)

Пользователь: создал remote, дал URL. Агент:

### 0. Уточнить (если не сказано)

- Класть ли `data/images` в git или только csv + инструкция про `nutrition.zip`?
- Пушить ли `best.pt`?
- Имя ветки: `main`.

### 1. Клонировать пустой репо

```bash
git clone <url> nutrition-submit
cd nutrition-submit
```

### 2. Перенести файлы из черновика

Источник: `…/p2_Nutrition/avo_Nutrition_rep/`  
**Не** делать `git init` внутри черновика поверх чужой истории `next_word`, если цель — **новый** репозиторий.

Скопировать в клон:

- `scripts/*.py`
- `avo_m25_555_nutrition.ipynb` (актуальный, после GPU — с outputs)
- `requirements.txt`, `README.md`, `.gitignore`
- `artifacts/.gitkeep`

Данные:

- Если junction в черновике — **скопировать реально** `dish.csv`, `ingredients.csv` и при необходимости `images/` (или положить `nutrition.zip` рядом и не коммитить zip).
- На Windows junction не попадёт в git как файлы — нужна обычная копия/`robocopy`.

### 3. Коммиты слоями (см. таблицу выше)

После каждого коммита — `git status` чистый для этого шага.

### 4. Push

```bash
git push -u origin main
```

Без `--force` на `main`, без правки git config пользователя.

### 5. Проверка «глазами ревьюера»

- Клонировать в temp на «чистую» машину / другую папку.
- Есть ли `scripts/`, ноутбук, README.
- Ячейка 0.2 находит `data/` **или** ясно написано про Upload `nutrition.zip`.
- Нет секретов, нет `C:\Users\…`.

## Связь с обучением

Пока GPU-прогон не закончен:

- в README строка MAE — заглушка;
- ноутбук может быть без финальных метрик;
- **не** пушить «финальный» results-коммит заранее.

Когда пользователь скажет «обучение готово»:

1. Обновить ноутбук с outputs в `avo_Nutrition_rep/`.
2. Дописать MAE в README.
3. Отдельным коммитом в GitHub-репо: results.
