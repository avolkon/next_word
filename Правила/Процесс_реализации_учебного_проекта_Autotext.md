# Пошаговый процесс реализации учебного проекта (пример: Autotext)

Документ описывает **фактический** порядок работ над проектом «Нейросеть для автодополнения текстов» (WikiText-2, LSTM / GRU / distilgpt2). Его можно использовать как образец для аналогичных модульных проектов.

---

## 0. Исходные материалы

| Что | Где лежит (итоговая структура репо) |
|-----|-------------------------------------|
| ТЗ и чек-лист сдачи | `p1_Autotext/Разработка/ТЗ_Autotext.txt` |
| План реализации | `p1_Autotext/Разработка/План_реализации_Autotext.txt` |
| Архитектурные спеки (ноутбук / полная) | `p1_Autotext/Разработка/Спеки/` |
| Эталон стиля кода | `Правила/Шаблоны/200_line_gpt_karpaty.py` |
| Шаблоны ролей | `Правила/Шаблоны/` |
| Сдаваемый ноутбук | `p1_Autotext/avo_m25_555_autotext.ipynb` |
| Colab-прогон (опционально) | `p1_Autotext/Autotext_full_Colab.ipynb` |

**Принцип:** один линейный ноутбук «сверху вниз», этапы 0–5 строго по ТЗ, выводы привязаны к чек-листу.

---

## 1. Подготовка (до кода)

1. **Прочитать ТЗ целиком** — бизнес-контекст, формальные этапы, чек-лист ревьюера.
2. **Зафиксировать план** — таблица «пункт чек-листа → ячейка ноутбука» (см. `План_реализации_Autotext.txt`).
3. **Выбрать профиль обучения:**
   - **Ноутбук** — быстрая проверка пайплайна на урезанных данных / CPU;
   - **Полная** — параметры старта из ТЗ, полный WikiText-2, GPU.
4. **Написать архитектурную спеку** под выбранный профиль (гиперпараметры, объём данных, ограничения ВМ).
5. **Согласовать формат сдачи:** один `.ipynb` без лишней обвязки; импорты один раз; эксперименты — отдельными ячейками.

**Результат этапа:** утверждённые ТЗ + план + спека, без дублирования логики в отдельных `.py`-модулях (если ТЗ требует ноутбук).

---

## 2. Каркас ноутбука (этапы 0–1)

1. **Этап 0**
   - Ячейка зависимостей (при необходимости — установка пакетов).
   - Ячейка импортов и **`seed = 42`** (torch, numpy, random).
   - Проверка `DEVICE` (cuda / cpu).

2. **Этап 1 — данные**
   - Загрузка `Salesforce/wikitext`, `wikitext-2-raw-v1` (актуальный id на Hugging Face).
   - Фильтр пустых строк.
   - **EDA:** примеры текстов, таблица статистик, **гистограмма длин** (`plt.show()`).
   - **Гиперпараметры после EDA** — отдельная ячейка с `# @title`, фиксация `SEQ_LEN`, `EMB_DIM`, … без сохранения артефактов на диск, если это не требует ТЗ.
   - Пословный словарь **только по train**, `MIN_FREQ`, `<unk>`.
   - Окна длины `seq_len`, сдвиг **X / Y на 1 токен** (демо из ТЗ).
   - `Dataset` + три `DataLoader` (train / val / test).

3. **Markdown между ячейками** — краткие выводы по фактам запуска (числа из вывода), не «на глаз».

**Критерий готовности:** все пункты чек-листа этапа 1 отмечаются галочкой.

---

## 3. Обучение RNN (этапы 2–3)

1. **Общий класс `LanguageModel`** — Embedding + LSTM|GRU + Linear, один цикл `train_model(rnn_type)`.
2. **Метрики:** train/val loss, **val perplexity = exp(CE)**.
3. **Gradient clipping** — `clip_grad_norm_` с `CLIP_NORM` из ТЗ.
4. **Early stopping** по val perplexity (например `PATIENCE = 2`).
5. **LSTM** — полный прогон, графики loss и perplexity (`plot_history`, только `plt.show()`).
6. **GRU** — те же гиперпараметры, сравнительная таблица: params, val/test ppl, секунды на эпоху.
7. **Вывод:** какая RNN лучше на **word-perplexity** и почему.

**Не обязательно для сдачи по ТЗ:** `torch.save`, zip, папки `OUT_DIR` — модель остаётся в переменных `lstm_result` / `gru_result`.

---

## 4. Трансформер (этап 4)

1. Загрузить `distilgpt2` + `GPT2TokenizerFast`.
2. Perplexity на **test** без дообучения (BPE-шкала).
3. Явно указать в тексте: **ppl distilgpt2 не сравним напрямую** с LSTM/GRU.
4. Примеры **топ-3** следующего токена на коротких контекстах.

---

## 5. Сводка и сдача (этап 5)

1. **Таблица** всех моделей: params, val/test ppl, время эпохи, шкала (word / BPE).
2. **5–10 одинаковых контекстов** — предсказания LSTM, GRU, distilgpt2.
3. **Рекомендация продакт-менеджеру:** on-device (компактный RNN) vs облако (трансформер); отделить продуктовую «картинку банка» от корпуса WikiText-2 (EN).
4. **Финальный ноутбук для ревью:**
   - титул и автор;
   - ТЗ в markdown;
   - рабочая часть **без Colab/Drive/zip**;
   - `# @title` на кодовых ячейках для удобства навигации.

**Пример имени:** `avo_m25_555_autotext.ipynb`.

---

## 6. Прогон на GPU (Colab / учебная ВМ)

1. Скопировать ноутбук в среду с GPU.
2. Запустить **Run all** или блоками 0 → 1 → 2 → 3 → 4 → 5 подряд (сессия 3–5 часов).
3. Зафиксировать числа в markdown-выводах (val/test ppl, время эпохи).
4. Перенести проверенные формулировки выводов в **сдаваемый** ноутбук без Colab-специфики.

---

## 7. Упаковка репозитория (как сделано для Autotext)

1. **`p1_Autotext/`** — пакет проекта:
   - `Разработка/` — ТЗ, план, спеки, иллюстрации;
   - ноутбуки на одном уровне с `Разработка/`.
2. **`Правила/`** — шаблоны, эталон Карпати, процесс и инструкции агентам.
3. **Коммиты по смыслу:** отдельно `p1_Autotext`, отдельно `Правила` (не смешивать с посторонними правками).

---

## 8. Типичные ошибки (из опыта Autotext)

| Ошибка | Как правильно |
|--------|----------------|
| Гиперпараметры до EDA | Сначала EDA, потом ячейка «зафиксированы параметры» |
| Сравнение ppl RNN и GPT напрямую | Две шкалы; качественно — общие контексты |
| `OUT_DIR`, zip, Drive | В сдаче не требуются; графики через `plt.show()` |
| `plt.show()` без построения fig | В ячейке должны быть `subplots` + `hist` / `plot` |
| Дубли ноутбуков и артефактов | Один канонический файл сдачи + опционально Colab |
| Преждевременные выводы «GRU лучше GPT» | Только после таблицы этапа 5 |
