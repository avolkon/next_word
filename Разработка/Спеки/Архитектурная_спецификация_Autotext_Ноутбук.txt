# Архитектурная спецификация: Autotext (вариант «Ноутбук»)

**Проект:** нейросеть для автодополнения текстов (предсказание следующего слова)  
**Версия:** 1.0  
**Статус:** Утверждена как рабочий локальный профиль  
**Синхронизация:** `ТЗ_Autotext.txt`, `План_реализации_Autotext.txt`  
**Цель профиля:** закрыть весь чек-лист ТЗ на обычном ноутбуке без GPU и без чужой ВМ

---

## 1. Назначение варианта

Локальный CPU-профиль. Абсолютный perplexity будет хуже полного варианта, но архитектура, сравнение LSTM/GRU/distilgpt2 и выводы для продакта остаются валидными.

В ячейке с гиперпараметрами и в финальных выводах явно указать:
`CONFIG = "laptop"` и что обучение шло на подвыборке / облегчённой сети.

---

## 2. Согласованные решения

| Пункт ТЗ | Реализация в профиле «Ноутбук» | Обоснование |
|----------|--------------------------------|-------------|
| WikiText-2 | Загрузка полного датасета, обучение на подвыборке train | EDA на полном наборе, ускорение обучения |
| Пословный словарь | Порог частоты выше, vocab меньше | Меньше параметров линейного слоя |
| LSTM / GRU | Embedding + RNN + Linear, 1 слой | Достаточно для демонстрации и сравнения |
| Hyperparams ТЗ | Уменьшены относительно старта из ТЗ | CPU без GPU |
| Gradient clipping | Обязателен | Стабильность при малом числе эпох |
| distilgpt2 | Без дообучения; perplexity на подвыборке test | Полный test на CPU слишком долгий |
| Сравнение моделей | Таблица + 5–10 общих контекстов | Качественное сравнение при разных шкалах ppl |
| Формат сдачи | Один Jupyter-ноутбук | Стиль Карпати: линейный рассказ |

## 3. Общая архитектура пайплайна

```text
WikiText-2 (datasets)
        │
        ▼
  Фильтр пустых строк + EDA
        │
        ▼
  Пословный словарь (только train, min_freq)
        │
        ▼
  Окна seq_len → Dataset / DataLoader (train/val/test)
        │
        ├──────────────┬────────────────┐
        ▼              ▼                ▼
   LSTM (train)   GRU (train)   distilgpt2 (eval only)
        │              │                │
        └──────────────┴────────────────┘
                       │
                       ▼
         Сводная таблица + примеры + рекомендация
```

Стиль кода: один ноутбук, константы сверху, минимум функций, один класс модели с аргументом `rnn_type`.

---

## 4. Контракты компонентов

### 4.1. Данные → словарь

```python
interface Vocab:
    word2idx: dict[str, int]
    idx2word: list[str]
    unk_token: "<unk>"
    # строится только по train
    # слова с count < MIN_FREQ → <unk>
```

Правила:
- валидация и тест не расширяют словарь;
- регистр: lower;
- разбиение: по пробелам (пословная токенизация по ТЗ).

### 4.2. Словарь → окна

```python
interface WindowBatch:
    X: LongTensor[B, seq_len - 1]   # вход
    Y: LongTensor[B, seq_len - 1]   # таргет = сдвиг на 1 вправо
```

Пример из ТЗ:
```text
["the","cat","sat","on","the","mat"]
X = ["the","cat","sat","on","the"]
Y = ["cat","sat","on","the","mat"]
```

Неполные хвосты короче `seq_len` отбрасываются (без паддинга).

### 4.3. Модель

```python
interface LanguageModel(nn.Module):
    emb: Embedding(vocab_size, emb_dim)
    rnn: LSTM | GRU (emb_dim → hidden_dim, num_layers)
    fc:  Linear(hidden_dim → vocab_size)
    forward(x) -> logits[B, T, vocab_size]
```

### 4.4. Метрика

```text
perplexity = exp(mean CrossEntropyLoss)
```

LSTM и GRU сравнимы между собой (общий словарь).  
distilgpt2 — отдельная шкала (BPE); в таблице пометить «не сопоставимо напрямую».

## 5. Гиперпараметры профиля «Ноутбук»

| Параметр | Значение | Комментарий |
|----------|----------|-------------|
| `CONFIG` | `"laptop"` | Переключатель в первой ячейке констант |
| `seed` | `42` | random / numpy / torch |
| `device` | `cpu` (или cuda, если вдруг есть) | Не требовать GPU |
| `SEQ_LEN` | `16` | Короче окна из ТЗ (32) |
| `EMB_DIM` | `64` | Вместо 128 |
| `HIDDEN_DIM` | `128` | Вместо 256 |
| `NUM_LAYERS` | `1` | Вместо 2 |
| `BATCH_SIZE` | `16` | Вместо 64 |
| `LR` | `1e-3` | Как в ТЗ |
| `EPOCHS` | `3` | Достаточно увидеть снижение val ppl |
| `CLIP_NORM` | `1.0` | Gradient clipping |
| `MIN_FREQ` | `5` (или `10`) | Сильнее режет словарь |
| `TRAIN_FRACTION` | `0.15` | 15% train для обучения |
| `VAL_FRACTION` | `1.0` или `0.5` | Val можно урезать для скорости |
| `TEST_FRACTION_RNN` | `0.5` | Test для LSTM/GRU |
| `TEST_FRACTION_GPT` | `0.05–0.10` | Подвыборка для distilgpt2 на CPU |
| `NUM_WORKERS` | `0` | Windows / ноутбук |
| Оптимизатор | Adam | — |
| Loss | CrossEntropyLoss | — |

Оценка объёма параметров (порядок):
- vocab ~5–15k при повышенном `MIN_FREQ`;
- LSTM/GRU: примерно сотни тысяч параметров, не миллионы.

Ориентир времени на CPU (зависит от машины):
- 1 эпоха LSTM/GRU: минуты, не часы;
- distilgpt2 eval на 5–10% test: приемлемо локально.

## 6. Этапы реализации (ячейки ноутбука)

### Этап 0. Подготовка
- Импорты, `seed = 42`, `CONFIG = "laptop"`.
- Проверка устройства (`torch.device`).

### Этап 1. Данные
- `load_dataset("wikitext", "wikitext-2-raw-v1")`.
- EDA: примеры, число документов, средняя длина, гистограмма.
- Словарь по train с `MIN_FREQ`.
- Окна, Dataset, DataLoader для train/val/test.
- Проверка сдвига на фразе `the cat sat on the mat`.

### Этап 2. LSTM
- Класс модели, цикл обучения, clipping.
- Печать train loss / val loss / val perplexity.
- Графики; val perplexity должна снижаться хотя бы на первых эпохах.

### Этап 3. GRU
- Тот же класс, `rnn_type="gru"`, те же гиперпараметры.
- Сравнение: perplexity, число параметров, секунды/эпоха.

### Этап 4. distilgpt2
- `GPT2LMHeadModel` + `GPT2TokenizerFast`, eval only.
- Perplexity на урезанном test; примеры предсказаний.
- Явная пометка о другой шкале метрики.

### Этап 5. Сводка
- Таблица: модель, параметры, val/test ppl, время эпохи.
- 5–10 одинаковых английских контекстов для всех моделей.
- Рекомендация продакту: качество vs размер vs скорость; оговорка про `CONFIG=laptop`.

---

## 7. Ограничения и честность отчётности

1. Не выдавать абсолютный perplexity этого профиля за результат полного обучения.
2. Картинка «Мой банк» — продуктовый контекст; корпус — английский WikiText-2.
3. В рекомендации продакту переносятся размер/скорость/качество подхода, не банковский русский словарь.
4. Если val perplexity не снижается — увеличить `EPOCHS` до 5 или `TRAIN_FRACTION` до 0.25, не переходя сразу на полный профиль.
